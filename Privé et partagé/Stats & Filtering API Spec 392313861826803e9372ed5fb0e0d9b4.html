Stats & Filtering API Spec

To support the needed filtering we need to update the /favorites api.

The Input stays the same, with the 3 most important being : languagePairs, learningStatus and listId.

However the answer from the API must be clarified so filters can be properly displayed.

What the API needs to give back is :

  • numTotalResults = Total count of Elements (favorites, ..) unfiltered.
  • numFilteredResults = Total count of results, with a max to 40 if user not premium.
  • Results = Actual results corresponding to the selected filters, same as today but with the limit at 40 if not premium
  • Status = Element that sums up all the counts of the different filters. It will contain
FieldWhatFilters applied
languagePairsFor each language pair in the whole considered database (favorites, history, ..), count of terms corresponding to the other 2 filtersLearningStatus + ListID
LearningStatusFor each status (defined list of statutes), count of terms corresponding to the other 2 filterslanguagePairs + ListID
ListIDFor each ListID in the whole considered database (favorites, history, …), count of terms corresponding to the other 2 filtersLearningStatus + languagePairs

API changelog — filtering - vocabulary lists & learning stats

1. GET /user/favouritesLists

Added a new parameter that, in combination with languagePairs parameter, we’ll return the lists with the right number of favs matching the filters.

New query parameter

ParamTypeRequiredDescription
favouriteLearningStatusenumnoReturn only lists that contain at least one non-removed favourite matching this learning status.

Example

GET /user/favouritesLists?favouriteLearningStatus=IN_PROGRESS&learningInfo=true&length=20

Response field semantics (VocabularyListResultDTO)

FieldBehavior
numFavouritesCount of non-removed favourites in the list (FAVOURITES.REMOVED = 0). Soft-deleted favourites still linked via the join table are excluded.
numFavourites + favouriteLearningStatusOverridden to the count of favourites matching that status (same filter as list inclusion).

Unchanged: numTotalResults / numStoredItems still reflect total lists (not narrowed by favouriteLearningStatus).

2. Learning stats — filtered vs total scope

Applies when learningStatus is returned on:

  • GET /user/favourites
  • GET /user/history
  • GET /user/favourites/readerPage/{uuid}

QueryResultDTO / nested learningStatus

FieldScope
numFilteredLearningResultsItem count with all filters except learningStatus. Denominator for filtered learning metrics.
Unfiltered fields (totalCards, memoryScore, totalItemsNotStarted, …)Total / full scope for the resource.
*Filtered fieldsSame filters as the list query except learningStatus is ignored.

LearnStatsSummaryDTO — filtered fields

FieldMeaning
totalCardsFilteredCards matching filters except learning status
activeCardsFiltered
ignoredCardsFiltered
memorizedOnceCardsFiltered
notStartedCardsFiltered
inProgressCardsFiltered
memoryScoreOnlyCardsFilteredCard-only progress (filtered)
memoryScoreFilteredsumProgress / (numFilteredLearningResults × 5)
totalFilteredItemsNotStartedfilteredItems − memorized − ignored − inProgress (clamped ≥ 0)

Client guidance: Use *Filtered + numFilteredLearningResults so changing learningStatus does not shrink the filtered denominator.

3. Language-pair counts (favourites & history)

On list endpoints that return per-pair counts (e.g. QueryLanguagePairResultDTO):

countByPair / language-pair map does not apply:

  • languagePairs
  • sourceLang / targetLang
  • notSourceLang / notTargetLang

Still applies: text filters, list id, learning status, dates, removed flags, and other non-language filters.

Intent: Clients can show the full language-pair breakdown while the result list is narrowed to one pair.

Learning Status filter

What to display in the filtering menu

Always display the 4 values : Learning, Mastered, Not Started and Ignored, whatever the counts.


Use the result of the learningStatus object in the request (favorites/history), see below

Values to use

  • Learning ⇒ learningStatus→inProgressCardsFiltered
  • Mastered ⇒ learningStatus→memorizedOnceCardsFiltered
  • Ignored ⇒ learningStatus→ignoredCardsFiltered
  • Not Started ⇒ numfilteredLearningResults - sum(learning+mastered+ignored)
